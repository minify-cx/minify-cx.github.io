Conformance · independent corpora and browser semantics

CSS evidence beyond hand-written fixtures.

The separate Minify++ conformance lab extracts transformable CSS cases from Web Platform Tests, runs Minify++ in batches, and compares the original and transformed stylesheets through Chromium's CSS parser and structured CSSOM.

31,137WPT-derived cases in the audited full snapshot
30,579structured-CSSOM passes before final defect repairs
17cases exposing real Minify++ defect families
0minify errors or browser/source rejection in that snapshot
This is not presented as 31,137/31,137.

The audited snapshot contained 558 CSSOM differences. Seventeen represented browser-relevant Minify++ changes, two came from UTF-16 extraction errors in the harness, and the remaining 539 reduced to verified lexical-trivia differences. A fresh full run of the corrected implementation and oracle is required before publishing a new all-cases result.

What the harness actually checks

Each source and minified stylesheet is parsed in Chromium. The structured view records rule types, selectors and conditions, declarations, priorities, child rules and exposed descriptor fields. Selectors remain exact because whitespace can be a descendant combinator. Values and conditional preludes use a conservative lexical canonicalizer that removes only trivia proven not to change token boundaries.

Raw CSSOM serialization is retained for every non-pass. Diagnostic differences are therefore inspectable rather than silently normalized away.

Defects the corpus found

  • Native-nesting descendant selector whitespace around &.
  • Attribute-selector namespace whitespace that changed invalid selectors into valid ones.
  • Escaped whitespace in ::part() identifiers.
  • Invalid declaration values joined into different browser-accepted constructs.
  • Bad-string newline trimming that changed CSS error recovery.

Those families were repaired in Minify++ and converted into small permanent regressions in the main repository. The corpus also found two UTF-16 decoding defects in the extractor itself, which were fixed separately rather than misreported as product failures.

Why this is stronger than idempotence

Running a minifier twice can prove that its output is stable, but consistently wrong output can also be stable. The browser-backed comparison asks whether Chromium sees the same selectors, rules and declarations before and after transformation.

One corpus, more than one minifier

The same extracted cases and Chromium oracle can run against Lightning CSS. Its adapter uses bounded multi-input batches and recursively isolates unsupported fixtures, making comparison possible without changing the corpus or pass criteria. The comparison infrastructure exists; this page does not claim a head-to-head result until one is recorded and reviewed.

Reproduce the lab

git clone https://github.com/minify-cx/minify-css-conformance.git
cd minify-css-conformance
python3 tools/conformance.py sync wpt
python3 tools/conformance.py extract-css
python3 tools/conformance.py run-css --cases work/wpt-css.jsonl

The standards suites stay upstream and are pinned by exact revision. Result JSON records the source revision, tool identity and raw evidence needed to audit disagreements.
